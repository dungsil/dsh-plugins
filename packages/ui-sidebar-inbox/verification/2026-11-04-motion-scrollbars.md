# 보관됨 펼침과 DSH 스크롤바 검증

## 환경

- 확인일: 2026-11-04, Asia/Seoul.
- 실행 중인 DSH가 보고한 클라이언트 release: `0.2.1-rc.5`, commit `d4db512`.
- 대상: `http://127.0.0.1:51471`에 연결된 데스크톱 GUI.
- 세션: `session-8d583640-d907-44f4-a53d-d568bdf4518e`.
- 최종 클라이언트 번들 revision: `0f40cf446a3c`.

## 실제 세션에서 확인한 동작

1. 최신 소스로 배포 파일을 빌드하고, 실행 중인 DSH의 클라이언트 모듈 갱신 기능으로 반영했다. 연결된 GUI에서 임시 검증 요청을 실행했다.
2. 보관됨을 접은 상태에서 펼치고 렌더링 프레임별 하단 영역 높이를 측정했다. 시작 시 138px, 95ms에 160.14px, 195ms에 273.25px, 395ms에 367.09px, 495ms에 373px이었다. 746px 목록의 절반인 373px을 넘지 않았다.
3. 보관됨 행과 표시 영역의 펼침 전환이 480ms인지 확인했다. 작업 중의 펼침은 기존 320ms로 유지했다. 전환 뒤 고정 높이를 해제하여 내용에 맞게 표시하는 것도 확인했다.
4. DSH 기본 목록과 새 스크롤 영역의 계산된 스크롤바 스타일을 비교했다. 두께는 모두 5px이었다. 표시 상태의 손잡이 색상은 모두 `rgb(229, 229, 229)`였으며, 테두리 0px, 모서리 반경 999px, 배경 영역 `content-box`도 일치했다. 기본 투명 상태도 같았다. 호버 색상은 DSH의 같은 테마 변수를 재사용한다.
5. 임시 검증 코드를 제외하고 다시 빌드했다. 최종 번들에 검증 코드가 없으며, 연결된 GUI에서도 임시 검증 제공자가 제거된 것을 확인했다.

## 자동 검사

- 최종 배포 파일로 실행한 테스트 29개가 모두 통과했다. 많은 보관 행의 높이 제한, 펼침 중 방향 전환, 작업 중 전환 유지, 동작 줄이기, DSH 스크롤바 규칙을 검사했다.
- 타입 검사, 린트, 포맷 검사, 공백 오류 검사를 통과했다.
