## 공통 in-place 업데이트

모든 플러그인은 DSH의 공통 업데이트 기능을 사용합니다. 버전 조회·패키지 교체·실패 복구는 DSH가 담당하며, 플러그인별 업데이트 코드나 활성화 플래그는 필요하지 않습니다.

버전 조회와 in-place 업데이트를 지원하는 DSH에서 **플러그인 → 설치됨 → 해당 플러그인 → 버전 → 업데이트**를 선택합니다. 한국어 UI 표시는 `locale-ko`가 제공하지만, 다른 플러그인의 업데이트에 `locale-ko`가 필요하지는 않습니다.

- npm 레지스트리에서 원래 패키지 이름으로 프로필에 직접 설치해야 합니다. Git, 로컬 경로, `.tgz`, `npm:` 별칭 설치는 버전 조회 대상이 아닙니다. tarball로 설치했다면 제거 후 npm 패키지 이름으로 다시 설치하세요.
- 현재 설치 버전보다 높은 버전이 npm에 게시되어야 합니다. PR 병합이나 GitHub Release만으로는 업데이트 목록에 나타나지 않습니다. 사전 릴리스는 **사전 릴리스 표시**를 선택합니다.
- 새 버전은 `dsh.bundle`을 선언하고 실행 중인 DSH의 버전 호환성 검사를 통과해야 합니다. 이 저장소는 각 패키지의 `engines.dsh`로 호환 범위를 명시합니다.
- HMR이 있으면 DSH가 기존 플러그인을 해제한 뒤 새 버전을 활성화합니다. HMR이 없으면 설치 후 DSH를 다시 시작해야 합니다. 설치에 실패하면 DSH가 기존 버전을 유지하거나 다시 설치하며, 복구까지 실패하면 **플러그인 추가**에서 다시 설치합니다.
- `korean-ime`를 직접 설치했다면 독립적으로 업데이트합니다. `locale-ko`의 의존성으로만 설치했다면 `locale-ko` 번들을 통해 관리하며, 설치되는 IME 버전은 해당 번들의 의존성 범위를 따릅니다.

버전 영역이 없다면 DSH의 기능 지원 여부와 설치 출처를 확인하세요. 업데이트 기능이 없는 DSH에서는 기존 제거·재설치 방식을 사용합니다.

### 개발 시 유지할 계약

공개 패키지는 semver 버전, `engines.dsh`, 배포에 포함되는 번들 패치와 빌드 결과물을 제공해야 합니다. 구성 요소 ID를 유지하고 다른 구성 요소를 포함하는 번들은 해당 패키지를 의존성으로 선언합니다. 새 버전의 활성화 전에 이전 등록이 해제되어야 하므로, 서비스 등록과 이벤트 리스너는 Cordis 컨텍스트 수명에 연결합니다.

`pnpm check`는 `scripts/plugin-package.test.mjs`에서 모든 공개 패키지의 공통 업데이트 계약을 검사하고, 각 런타임 테스트에서 해제 후 새 모듈 인스턴스의 재등록을 확인합니다. 한국어 선택 유지, IME 전송 중복 방지, 윤문 스킬 재등록, ADHD 프롬프트의 단일 등록을 검증합니다. npm 다운로드·실패 복구 자체는 DSH가 담당하며 이 저장소의 테스트는 실제 레지스트리 업데이트를 실행하지 않습니다.

## 릴리스

`main`의 Conventional Commits를 분석하여 패키지별 버전과 변경 이력을 자동으로 관리합니다.
changeset 작성이나 별도의 버전 PR은 필요하지 않습니다.

1. `feat(locale-ko): 번역 추가`처럼 변경 내용을 커밋하고 `main`에 병합합니다.
   Squash merge를 사용한다면 최종 커밋 메시지가 되는 PR 제목에도 이 형식을 사용합니다.
2. GitHub Actions에서 `main`을 대상으로 **Release**를 한 번 수동 실행합니다.
   변경된 패키지의 버전·`CHANGELOG.md`를 갱신한 뒤 npm 게시, 릴리스 커밋·패키지별 태그,
   `.tgz`가 첨부된 GitHub Release 생성을 순서대로 진행합니다.

| 커밋                                                  | 버전 증가                              |
| ----------------------------------------------------- | -------------------------------------- |
| `fix`, `perf`, `revert`                               | patch                                  |
| `feat`                                                | minor                                  |
| `feat!`, `fix!` 등 `!` 또는 본문의 `BREAKING CHANGE:` | major                                  |
| `docs`, `test`, `chore`, `ci` 등                      | breaking change가 없으면 배포하지 않음 |

대상 패키지는 scope 문자열이 아니라 **커밋에서 실제로 수정한 패키지 디렉터리**로 결정합니다.
여러 패키지를 수정한 커밋은 각각에 반영하고, 루트 문서나 CI만 수정한 커밋은 플러그인을 배포하지 않습니다.
새 패키지는 `0.0.0`에서 시작하면 첫 `feat` 커밋으로 `0.1.0`을 배포합니다.
기존 `locale-ko`는 `v0.3.1` 이력을 이어받고, 이후 태그는 `@dungsil/dsh-plugin-locale-ko@0.4.0` 형식을 사용합니다.
private 패키지는 배포 대상에서 제외합니다.

`pnpm release --dry-run`으로 게시·커밋·태그 생성 없이 예정된 버전과 릴리스 노트를 확인할 수 있습니다.
배포할 커밋이 없으면 새 버전을 만들지 않습니다.

npm 게시는 패키지별 Trusted Publisher 설정이 필요합니다. 새 패키지는 최초 게시 인증도 준비해야 합니다.
